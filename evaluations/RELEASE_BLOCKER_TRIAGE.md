## Utility triage

The previously proven false-PASS defect is fixed: the final `bad` predicate now
includes `not report["stage_company_database_matches_source"]`. The focused
regression suite recorded **4/4 PASS** after that change.

Remaining issues are validation gaps, not newly repaired defects:

- manifest JSON is loaded without schema, nonempty-count, SHA-format or relative
  path validation;
- absolute and `..` manifest keys are not rejected or confined;
- directory/ancestor-link and unexpected-file inventories are incomplete;
- the Qdrant probe permits an empty collection through `all(...)` and does not
  assert scanned point count against the reported count;
- missing live reports and integrity mismatches share a generic failure bucket;
- exceptions can occur before a fresh structured report is written.

These gaps require a defined attestation contract before safe changes. They were
not edited in this read-only task.

### `.evaluation_runtime/render_master_final.py`

The current main path is fail-closed: it requires the missing final JSON/receipt
inputs and its classification returns `C. RELEASE BLOCKED` when gate evidence is
absent. The `status` helper also keeps absent/non-completed rows from becoming PASS.

Validation remains incomplete. The helper can return a positive candidate if called
with an arbitrary `{name: "PASS"}` gate map and empty suites; it does not validate
gate identities, report schemas, receipt/report agreement, provenance, or count
consistency. It also contains hardcoded matrix claims and writes several outputs
before all later validation is known. These are latent integrity risks, not evidence
that a misleading report was generated in this task. The renderer was not executed.
